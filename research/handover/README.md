## 2 · "两个版本"分别存在哪三处（三重保险）

1. **GitHub**（最可靠，不用做任何事）
   三个回退点**都是 `origin/main` 的祖先提交** —— 任何机器 clone 下来都能 `git checkout` 到。
   **它们本来就在 GitHub 上，不需要额外备份。**

2. **本地 tag**
   三个内核仓库各有一个 annotated tag **`pre-three-way-interop`**（本地，**还没 push**）。
   想让它在 GitHub 上也看得见（纯标签，不改历史、不动 `main`）：
   ```bash
   cd /root/deepseek/repos/<内核仓库>
   git push origin pre-three-way-interop
   ```

3. **RN 上的冻结快照**（不依赖 GitHub、也不依赖这台登录机）
   ```
   ssh rn 'ls -la /root/catmi/_versions/'
   /root/catmi/_versions/
   ├── MANIFEST.txt            ← 与本文件夹里的 frozen-snapshots-MANIFEST.txt 同源
   ├── pre-interop/            ← 「原本那版」三个 tarball
   └── current/                ← 「现在这版」三个 tarball
   ```
   ⚠ **它们是冻结的源码快照，不是运行中的服务**；目录里没有进程、没有端口，**别直接启动**
   （会撞端口、撞分享服务的 token 命名空间）。

## 4 · 三条可选路线（详细在 `handover-interop-rollback.md` §5）

| 路线 | 一句话 | 代价 | 建议 |
|---|---|---|---|
| **方案 0（推荐）** | **在当前版上加一个开关**：`legacy` 模式下服务端只发原生、地址不带声明，客户端跳过声明决策 → 行为回到原状 | 只增不改，一行环境变量切换；**一条真修复都不丢**。但代码里仍留着互通实现 | ✅ **先做这个** |
| 方案 B | 从当前版**手工摘掉**互通（保留全部真修复） | 外科手术，共享文件里互通与非互通代码**交织**，1~2 天 + 完整回归 | 确定以后不要互通时再做 |
| 方案 C | 回到 `c0a5c19` 再**手工补** 5 个真修复 | **最贵**：实测 5/6 个修复会冲突，要手工解 | 只在要"一条干净历史线"时 |

**实测数据（这决定了为什么不推荐 C）**：把"非互通真修复"从回退点往上挑 ——
**SB 6 个里只有 1 个干净、5 个冲突；M 3 个里 2 个干净、1 个冲突**。
根因：这些修复是在互通提交**之后**做的，文件上下文已经变了。

> 📌 **实际执行的是「方案 B（从 main 摘互通）」**，三家都已完成并推送（见 §0 与三份
> `*-rollback-executed.md`）；只有 **M** 因为修复少、且两条能干净 cherry-pick，走的是
> "从回退点重建 + 挑修复"。上面三条路线现在只作**决策依据**保留。
